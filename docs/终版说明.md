# Bridge75 ANSI NoRGB 终版

日常使用文件为 `bridge75_ansi_norgb_final.bin`。刷写后退出 DFU，在空白文本编辑器按 Fn+D，松开按键后诊断以 `bridge75-final` 开头。`SHA256SUMS-final` 包含终版和复位唤醒回退版的校验值。

## 相对 diag3 的改动

- MCU 唤醒时恢复外设，并保留 QMK 已扫描到的按键和修饰键。按键持续按住时阻止进入休眠。
- 优先处理 UART 接收。在重试边界仍识别有效的迟到 ACK，避免本来已经确认的消息耗尽重试额度并触发重连。
- USB 恢复由 QMK 的 USB 事件处理。退出 USB 模式时清理休眠跟踪状态，Fn+反引号只在按下时切换。
- 换主机时取消旧主机的诊断输出。切到 USB 时取消尚未触发的无线长按配对。重置 EEPROM 后恢复状态灯配置，无效的旧蓝牙槽位回到 USB。
- 修正设备名称长度和 VID/PID 打包的边界处理。

## 验证记录

- 从改动前源码重编的二进制与用户刷写的 diag3 逐字节一致。该版本在蓝牙 1、USB 拔线且 `sleep=0` 的条件下通过了 6 分钟和 35 分钟闲置测试。两次日志均显示矩阵按键唤醒。
- 终版与复位唤醒回退版均编译通过。QMK lint、UART 协议与百万次队列模型、低功耗、USB 和板级回归均通过。源码补丁对应 QMK 基线 `33292390974c75362ca30873c482d052e0bd7a63`。
- 终版待实机复测。先确认 USB 打字和蓝牙 1 切换，再拔 USB 重测 6 分钟和 35 分钟。唤醒后的首键可用 Shift+字母验证修饰键。此前报告的 Fn 指示灯仍需肉眼确认，串口计数无法证明 LED 亮起。2.4 GHz、模块休眠开启和待机耗电也缺少实测结果。

如终版出现回归，可刷回实机已通过的 `bridge75_ansi_norgb_diag3.bin`。
