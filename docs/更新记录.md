# Bridge75 固件更新记录

每次构建的文件名和 Fn+D 诊断前缀都带标签与构建时间，例如 `bridge75_ansi_norgb_power_20261113-2349.bin` 对应 `bridge75-power-20261113-2349`。两者一致才说明刷对了。新条目写在最上面。

## via2 20261121-0202（当前最新，待实机测试）

文件 `bridge75_ansi_norgb_via2_20261121-0202.bin`（复位回退版 `..._resetwake.bin`），校验 `SHA256SUMS-via2-20261121-0202`。在 via 20261121-0106 基础上：

- **清理未实现的自定义键位。** 从 `info.json` 和 VIA 定义删除 `BT_SW`、`BT_VOL`、`USBSLP`、`RGB_TEST`，自定义键位从 11 项缩为 8 项：BT_HOST1–3、BT_2_4G、BT_USB、BR_DIAG、BR_BAT、BR_SLEEP。`BR_DIAG`/`BR_SLEEP` 的索引变为 5/7；旧键图由 VIA magic 自动重置，不需要迁移。
- **新增电量键 `BR_BAT`（Fn+B）。** Windows 和 Mac 的 Fn 层都在 B 位置放了它；按下后以逐字符方式输出 `bat=NN`，与 Fn+D 诊断共用输出缓冲，两种输出不会交错。只在本机 USB 或无线已连接时输出；模块尚未回报电量前数值可能仍是默认 100。
- **输出末尾不再带回车。** Fn+D 和 Fn+B 的输出都不再以 `\n` 结尾，也就是不会自动按 Enter：光标停在输出末尾，不会在编辑器里换行、触发搜索/发送等动作。代价是连按两次会接在同一行。
- **默认键位改成标准布局：Fn+1/2/3 蓝牙 1–3、Fn+4 2.4G、Fn+5 有线 USB。** 模块休眠键从 Fn+5 移到 Fn+`（Esc 下面那个键）；Fn+Esc 仍是清 EEPROM。Windows / Mac 两套 Fn 层一致。
- **VIA 定义缩为 8 项。** `docs/via/bridge75-norgb-via.json` 的 `customKeycodes` 与 `info.json` 顺序一致。via 版（11 项）的旧 JSON 不能用于 via2，反之亦然。
- 主机回归新增 `BR_DIAG`/`BR_BAT` 的 `output_kind` 检查；lint、三组主机测试和两个变体编译通过，无警告。日志在 `firmware/logs-via2-20261121-0202/`。

建议实机检查：

1. Fn+D 前缀为 `bridge75-via2-20261121-0202`，USB/蓝牙/2.4G 打字正常；输出结束后光标停在同一行，没有回车。
2. Fn+B 在 USB 和蓝牙下各按一次，确认输出 `bat=NN`，数值与 Fn+D 里的 `bat=` 一致。
3. Fn+1/2/3/4/5 依次切到蓝牙 1/2/3、2.4G、有线；Fn+` 切换并保存模块休眠；Fn+Esc 清 EEPROM 后恢复默认键位。
4. 有线 VIA：加载新的 `docs/via/bridge75-norgb-via.json`，确认只剩 8 个自定义键位，`DIAG`、`BAT`、`SLEEP` 可分配且行为正确。
5. 切到蓝牙/2.4G 后 VIA 里的键盘消失，无线行为与 via 版一致。

同一批的 20261121-0156 构建（输出带尾部回车、Fn+5 为模块休眠）已被本构建取代。

## via 20261121-0106（已被 via2 取代）

文件 `bridge75_ansi_norgb_via_20261121-0106.bin`（复位回退版 `..._resetwake.bin`），校验 `SHA256SUMS-via-20261121-0106`。在 power 20261113-2349 基础上：

- **仅 USB 有线支持 VIA（RAW HID）。** `ansi_norgb/keymaps/default/rules.mk` 打开 `VIA_ENABLE`，QMK 在 USB 描述符里加入 Usage Page `0xFF60`、Usage `0x61` 的厂商自定义接口；VIA Web 通过它读写动态键图。构建时 QMK 会自动打开 `RAW_ENABLE` 和 `DYNAMIC_KEYMAP_ENABLE`。`VIA_ENABLE` 放在 keymap 层是因为 `qmk lint` 禁止键盘级 VIA，而 keymap 目录本身不能叫 `via`。
- **无线不隧道 RAW HID。** 切到蓝牙/2.4G 时 `transport.c` 会 `usbStop` + `usbDisconnectBus`，USB 设备消失，VIA 自然不可用；`wireless.mk` 不再编译厂商那套按源码行号重命名的 `md_raw.c`，只允许声明了 `BRIDGE75_USB_RAW_HID=yes` 的 USB-only 用法。
- **新增 VIA 3 定义 `docs/via/bridge75-norgb-via.json`。** 6×15 矩阵、4 层、11 个自定义键位（BT_HOST1–3、BT_2_4G、BT_USB、BT_SW、BT_VOL、USBSLP、RGB_TEST、BR_DIAG、BR_SLEEP）。`customKeycodes` 的顺序必须与 `info.json` 的 `keycodes` 一致，才能对上 `QK_KB_*`。其中 BT_SW、BT_VOL、USBSLP、RGB_TEST 目前没有处理函数，是为保持 BR_DIAG/BR_SLEEP 索引不变而占位的，VIA 里标注为“本固件未实现”；不要把它们当可用功能。定义里没有 RGB 菜单，灯效仍由固件的状态灯逻辑控制。本版 JSON 保留 11 项，只配 via 20261121-0106。
- **Fn+Esc 仍会重置键图。** QMK 在 VIA 下由 `eeconfig_init_quantum()` 调用 `dynamic_keymap_reset()`，恢复编译进固件的默认键位并回到 USB 模式。

构建通过 lint、三组主机回归和两个变体编译，无警告；固件里能查到 `06 60 ff 09 61` 的 RAW HID 描述符。日志在 `firmware/logs-via-20261121-0106/`。

建议实机检查：

1. 有线连接，打开 usevia.app → Design → Load Draft Definition，选择 `docs/via/bridge75-norgb-via.json`，确认出现 `Bridge75 NoRGB`，能读取并改写键位；自定义键位（切 USB/蓝牙/2.4G、Fn+D）可以在 VIA 里选到。
2. 改一个键后拔插 USB，确认设置保留；按 Fn+Esc 后确认恢复默认键位并回到 USB 模式。
3. Fn+D 前缀为 `bridge75-via-20261121-0106`，USB/蓝牙/2.4G 打字正常。
4. 切到蓝牙或 2.4G 后，VIA 里的 `Bridge75 NoRGB` 应消失；接收器自带的 `Bridge75 2.4G` 可能仍在列表里，那是闭源接收器的接口，配置不到本固件。
5. 首次刷入 VIA 版时 VIA magic 无效，会重建动态键图；确认之前保存的无线模式和模块休眠设置（诊断里的 `dev`、`sleep`）是否保留。

## 构建流程说明（2026-11-14）

源码迁到 GitHub 私有仓库 `AhaYue/bridge75-qmk`，在仓库根目录运行 `BRIDGE75_TAG=<标签> ./build.sh`。每次构建的日志自动写进 `firmware/logs-<标签>-<时间>/`。固件本身没有变化，最新构建见上方的 via2 20261121-0156。

## power 20261113-2349（已被 via/via2 取代，无线项仍待测）

文件 `bridge75_ansi_norgb_power_20261113-2349.bin`，校验 `SHA256SUMS-power-20261113-2349`，源码 `bridge75-official-qmk-power.patch`。在 ack 20261113-2237 基础上：

- **诊断加入电量 `bat=`**，取自模块上报的百分比。没有仪器时，可对比闲置 24 小时前后的 `bat` 估算待机耗电。模块回复前显示默认值 100，开机后首次查询会立即发出，通常一两秒内就是真实值。
- **电量查询从每 3 秒改为每 30 秒**（`WLS_INQUIRY_BAT_TIME`），开机后先立即查询一次。只在无线模式且未进入低功耗时查询。
- **断线重连间隔逐步拉长。** 原来断线期间每 500 ms 重新选择一次设备并发送配置；现在从 500 ms 起每次翻倍，封顶 10 秒（`MD_RECONNECT_MIN` / `MD_RECONNECT_MAX`）。断线期间按键、收到已连接、重试耗尽、切换设备和 STOP 唤醒都会回到 500 ms，所以正常使用时重连速度不变；主机不在时 UART 不再持续忙碌，MCU 更容易进入 STOP。
- 新增主机测试 `reconnect_backoff`、`battery_inquiry_schedule`，两者在 ack 版代码上都会失败。全部测试、lint 和两个变体编译通过，无警告。日志在 `firmware/logs-power-20261113-2349/`。

建议实机检查：
1. Fn+D 前缀为 `bridge75-power-20261113-2349`，`bat=` 为合理数值，USB/蓝牙/2.4G 打字正常。
2. 主机离开：保持蓝牙模式关闭电脑蓝牙 30–60 分钟，再打开，确认能自动回连（最长约 10 秒，按键可立即触发），Fn+D 看 `wakes` 和 `source`。`source=2` 表示被模块消息唤醒。
3. 闲置前后各记一次 `bat`，估算待机耗电。

## ack 20261113-2237

修正 ACK 对账：ACK 不带序号，按发送次数记欠账，欠账错估时不再连锁；重发超时 10 ms 改 30 ms；诊断前缀开始带标签和时间。实机 USB、蓝牙、2.4G 均验证每丢一份正好重发 2 次，丢包率 0.14%–0.8%，`bad=0`。2.4G 下出现过 `drops=76`，尚未定性。详见 `ack版说明.md`，日志在 `logs-ack-20261113-2237/`。
