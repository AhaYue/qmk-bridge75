# Bridge75 ANSI 无灯版：执行与验证

## 基线与范围

- 原项目：`qmk_firmware-em-bridge75`，`da9e806e3967109694ab4951244515219e444690`，保留原工作目录。
- 作者无线来源：`qmk_wireless_rc8`，`c0f86de489c6d5d2ae62a8f4e70f7ae08a9c4031`（wireless / RC8）。
- 官方目标：`qmk-bridge75-ansi-norgb`，`33292390974c75362ca30873c482d052e0bd7a63`，本地分支 `bridge75-norgb`。
- 仅移植公共无线目录、Bridge75 公共硬件文件和 ANSI NoRGB 变体；不修改 QMK 核心，不刷写键盘。

## 多 agent 分工

1. 协议 agent：报告缓冲、发送重试、接收解析、NKRO、主机测试。
2. 低功耗 agent：MCU STOP、UART 恢复、睡眠取消、USB 唤醒回调、主机测试。
3. 键盘适配 agent：键码、EEPROM、诊断与模块睡眠开关、使用说明、交叉审查。
4. 主 agent：固定来源、工具链、官方移植、构建脚本、集成与最终固件。

文件所有权分离；接口通过 agent 消息协调；交叉审查后统一重建。

## 对原计划的修正

- 本地原分支的目标叫 `shortcut/bridge75_nolight`，无线目录是 `modules/westberry/wireless`；RC8 才采用新目录。
- 队列覆盖未在默认 40 描述符、50 字节上限下复现，实际源码百万次随机操作通过，因此保留现有队列，不将推测当作已证实缺陷。
- QMK `uart_init()` 是一次性的，软恢复使用板级 `sdStop/sdStart`，并在中断恢复后重建协议状态。
- 官方主循环会自行调用 user housekeeping；新增板级回调，避免重复定义及重复调用。
- RC8 的 `LT(0, 自定义键码)` 会截断键码，改为直接键码与长按配对计时。
- 移除基于源码行号的 RAW HID 注入；本目标明确不支持 VIA / RAW HID。
- 复位回退版会丢失复位前 RAM 计数及首键缓冲，它不是“无损唤醒”的保证。

## 工具与重建

Homebrew 安装的 QMK 1.1.8 指向缺失的 Python 3.13，使用工作区 `.venv-qmk` 安装 QMK CLI 1.2.0。ARM GCC 8 与 binutils 使用 Homebrew 工具链。

执行 `qmk-bridge75-ansi-norgb/tools/bridge75/build.sh`，生成两个固件、SHA256、lint 和主机测试日志。测试使用真实生产 C 源码，驱动/时间由主机桩模拟。

本机 AddressSanitizer 在进入 main 前持续占用 CPU，未将其记为通过；协议测试使用 UndefinedBehaviorSanitizer。硬件寄存器、晶振、时序和闭源模块无法由桩测试证明。

## 刷机与实机验证

详见 `qmk-bridge75-ansi-norgb/keyboards/shortcut/bridge75/readme.md`。

先刷 `bridge75_ansi_norgb.bin`。如软唤醒异常，改刷 `bridge75_ansi_norgb_resetwake.bin`。按住 Esc 插线进入 wb32-dfu，再用 QMK Toolbox 刷写。旧 VIA 定义不适用。

- Fn+1/2/3：蓝牙；Fn+4：2.4G；Fn+反引号：USB。长按 Fn+1/2/3/4 一秒进入配对。
- Fn+5：切换模块 30 分钟睡眠策略并保存；默认关闭。MCU 仍在约 5 分钟后 STOP。
- Fn+D：在空白文本编辑器中，松开所有键后输出诊断；输出期间保持空闲。
- 检查所有连接模式、配对、Caps/电量/连接指示灯。
- 无线闲置 6 分钟及 35 分钟后立即输入完整单词；保存诊断，再开启模块睡眠重复测试。
- 检查按住修饰键切换设备、NKRO 满槽换键及待机耗电。

未进行实机刷写或 35 分钟休眠测试；软唤醒效果、模块是否接受禁用休眠命令与耗电变化均待实测。

## 最终本机验证结果

- 两个变体均编译、链接成功，构建日志无编译警告/错误。
- 软唤醒版：43,696 字节；复位回退版：43,704 字节。
- `qmk lint` 通过；协议 UBSan 主机测试通过；低功耗与 USB 状态机测试通过。
- `SHA256SUMS` 已核验两个产物；源码补丁为 `bridge75-official-qmk.patch`，应用基线为上述官方提交。
- 切设备先按 ACK 顺序发送六类释放帧再切换；旧无线链路不可达时，无法保证旧主机收到释放。
- 源码已经暂存，未提交；旧项目未做工作区代码修改。
